## Required manual browser smoke tests

Before declaring a public 1.0.0 release, install each unpacked folder in its target browser and complete the following checks. This step matters because browser APIs, download behavior, restricted page rules, and store-signing requirements must be validated in the actual browser release channel.

| Test | Chrome / Edge / Brave / Opera | Firefox |
| --- | --- | --- |
| Load package | Load `extension/dist/chromium` with Developer mode | Load `extension/dist/firefox/manifest.json` as a temporary add-on |
| Activate annotation surface | Click toolbar icon and use `Alt` + `Shift` + `A` on an HTTPS page | Same |
| Tool coverage | Create pen, highlighter, text, line, arrow, rectangle, ellipse, and stamp annotations | Same |
| Editing | Select, move, duplicate, delete, undo, and redo marks | Same |
| Local persistence | Reload a page and confirm its project restores | Same |
| Archive | Open Workspace; search, export, import, and delete a local project | Same |
| Scratch Sheet | Create, draw on, save, reopen, and export a Scratch Sheet | Same |
| Visibility | Hide/show a layer and test Browse mode against normal webpage links | Same |
| Export | Export JSON and visible annotated PNG capture | Same; note Firefox capture behavior |
| Restricted pages | Confirm a protected browser page fails safely without injected UI | Same |
| Accessibility | Navigate controls by keyboard and test system reduced-motion mode | Same |

## GitHub handoff

Create a public repository, push the full project, and attach both ZIP files to a tagged GitHub Release. The included GitHub Actions workflow runs the syntax checks, creates both package directories, and verifies their required contents on pushes and pull requests. Branch-protection rules should require that workflow before merging release changes.

After a manual smoke test, submit the Chromium ZIP to Chrome Web Store and Microsoft Edge Add-ons as separate listings. Submit the Firefox ZIP to Mozilla Add-ons for signing and review. GitHub Releases can distribute source and developer-mode installation artifacts, but ordinary users need store publication for a frictionless standard installation experience.

## Release notes draft

> **Annotaura 1.0.0 introduces an original local-first annotation workspace for live webpages.** It provides an edge-mounted Margin Rail, editable marks and notes, arrows and shapes, evidence stamps, local page-aware projects, searchable archive views, Scratch Sheets, JSON backup and import, a visible annotated-page capture, templates, and separate Manifest V3 packages for Chromium and Firefox. This first release contains no account, cloud synchronization, remote annotation storage, analytics, or remotely hosted code.
